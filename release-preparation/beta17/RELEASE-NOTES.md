Smart Connector for Autodesk Revit and AutoCAD 1.1.0

Lean core: Smart Connector now runs nothing in the background. This removes the behaviour that antivirus programs such as Kaspersky treat as a PowerShell "agent", and it gives IT a much smaller footprint to approve.

- No scheduled tasks and no notification-area agent. Updating from 1.0.0 or an earlier beta removes the four tasks earlier versions created (connector agent, usage report, weekly Skills Sync, update alerts) and the agent's restart copy. The running agent exits after the update.
- Update checks happen when you open Revit, AutoCAD or Smart Connector, at most once a day: one small download of the public latest.json. You are asked "Update now" or "Later". Update now opens a visible update window, which waits for Revit and AutoCAD to close and then installs. Nothing installs without your choice.
- Weekly Skills Sync reminder: on team computers, when the last successful sync is more than a week old, Revit, AutoCAD and the Smart Connector app remind you once a day. Switch it off in Settings.
- Usage counts for the administrator's dashboard are sent only when you run Skills Sync, never on a schedule. Setup no longer starts a hidden Skills Sync after installing.
- Removed: the optional Claude remote gateway (a local web server published to the internet through a Cloudflare tunnel). On PCs that used it, the update stops it, removes its start-up entry and deletes its stored credentials. Administrators should also revoke those tunnels in Cloudflare. Claude Desktop, Claude Code and Codex on the same PC work as before.
- In AutoCAD the daily check starts with the first Smart Connector button you use in a session. Loading anything at AutoCAD startup made AutoCAD ask SECURELOAD for every drawing, so that is avoided.
- Setup file: the setup .exe now only installs files (the connector and a Start menu entry) and runs no program or script. Open Smart Connector from the Start menu to finish: the setup window asks which AI apps and Autodesk programs to connect, as before. The Start menu entry opens the installed Smart Connector program, so no script runs from it.
- Compiled MCP server: Claude and Codex now start `bin\SmartConnector.exe`, a compiled program, instead of running the PowerShell bridge scripts. It offers the same Revit and AutoCAD tools with the same arguments and safety checks (one model change at a time, read-only tools stay read-only, skill files are read only from the approved folders). It is compiled by the release build, never on your PC. Setup re-points Claude Desktop, Claude Code and Codex to it; an install without it keeps using the PowerShell bridge. Before an update replaces the files, a running copy of the connector is closed; Claude and Codex start it again the next time they open (setup already restarts Claude Desktop when it re-points it).
- Compiled windows: the Smart Connector app, the setup window and the Skills Sync, Check Updates and Connection Status windows are now part of `bin\SmartConnector.exe` instead of PowerShell scripts, with the same sections, wording and look. The Start menu entry, the Revit and AutoCAD buttons and the end of setup open the program; the work behind the buttons (install, repair, Skills Sync, update check) still runs the existing setup scripts, and the update window stays as it was. An install without the program uses the PowerShell windows as before.
- Compiled Skills Sync: the Skills Sync button in Revit and AutoCAD, the Smart Connector app and the usage upload now run inside `bin\SmartConnector.exe` (`SmartConnector.exe skills sync`, `preview`, `collect`, `submit`, `usage`, `codex-sync`, `retire-tasks`, `configure` and `initialize`) instead of PowerShell scripts. They read and write the same files under `%LOCALAPPDATA%\AutodeskMcpSkillCollection`, send the same requests to the team skill service, apply the same checks (credentials, personal paths, client locations, e-mail addresses and links stay out of every submission), keep the same ledgers and the same log and result text. The PowerShell scripts stay in the package as the fallback for a copy taken from the repository, where `bin\SmartConnector.exe` is not installed.
- Compiled install engine: setup, Repair and updates now run inside `bin\SmartConnector.exe` (`SmartConnector.exe engine --action Install|Update|CheckUpdate|Status|...`) instead of `installer\Setup-BimCad.ps1`, with the same steps, messages and results. Installing the files, connecting Claude Desktop, Claude Code and Codex, the AutoCAD panel, the Revit add-in build, joining the team service and the update check no longer start PowerShell. The update no longer swaps the whole install folder: it downloads and verifies the release, stops only the other Smart Connector programs of this install, and replaces the files in place. A file in use (including the program itself while it runs the update) is set aside as `<name>.old` and deleted the next time any Smart Connector command starts; if the replacement fails, everything is put back. The update window (`SmartConnector.exe action --action InstallUpdate`) is part of the program too, and Revit and AutoCAD open it. An install without the program (a copy taken from the repository) keeps using the PowerShell scripts.
- Setup file without scripts: the setup .exe now installs only the compiled program (`bin\SmartConnector.exe`) and its data (icons, the skill library, the Revit and AutoCAD source files). No PowerShell, batch or other script of the connector is installed; the first open, the windows, Repair, updates and Skills Sync all run inside the program. Helper scripts that some approved skills carry inside the skill library are unchanged. A copy of the connector taken from the repository still contains the scripts and keeps using them.
- One setup: the setup .exe copies the files (a short progress bar) and opens the Smart Connector Setup window straight away: terms of use, AI apps, Revit add-in, AutoCAD panel with AI Markup, and the team. Nothing has to be opened from the Start menu to finish.
- Team registration in the normal setup: every PC that has not joined yet is asked for name, work email and the team code the administrator hands out, so its skills and usage appear on the team dashboard. The setup file carries no code; a TEAM build that carries one skips the code field. Joining can be unticked.
- Team workflow skills and the daily update check are always installed; they are no longer options in setup.
- Claude Code and Codex are found when they were installed after Windows started, through npm, winget or the Claude Code installer: Smart Connector reads the current PATH from Windows and looks in those installers' folders.
- Fixed: setup could stay on "Connect Claude Desktop..." after every step had finished, until Claude Desktop was closed. Claude Desktop is now restarted through the Windows shell, and the setup window finishes a few seconds after the install engine ends.
- Fixed: in the Revit ribbon, Open Connector and the small buttons (Check updates, Settings, Diagnostics, Help) showed only the top-left quarter of their icons. Each icon is now drawn at the size of its button (32 x 32 or 16 x 16), and the automated tests check every ribbon icon's size.
- Fixed: the setup .exe no longer asks for a Start menu folder and no longer tries to close programs ("applications are using files", then "unable to close all applications"). A running Smart Connector, such as the connection Claude started, keeps its program file in use; setup now moves that file aside and installs the new one, and the old copy is deleted the next time Smart Connector starts.
- ChatGPT Desktop: on a PC with ChatGPT Desktop (or the Codex app) but without the Codex command-line tool, setup now connects Smart Connector through Codex's settings file (%USERPROFILE%\.codex\config.toml), which ChatGPT Desktop reads. Other servers and settings in that file are kept. The setup window lists it as "Codex / ChatGPT Desktop". Restart ChatGPT Desktop after setup. Community reports say the tools may show only in ChatGPT Desktop's Codex mode on Windows, not in normal chats.
- Fixed: after installing with the setup .exe, every Smart Connector button in the Revit ribbon reported "The Smart Connector installation folder could not be found". The add-in looked for a setup script that the setup .exe no longer installs; it now recognises the installed program as well.
- Update channel without scripts: the Smart Connector program now reads `smart-connector.json` (the script-free release ZIP, `Smart-Connector-<version>.zip`) instead of `latest.json`, which stays for PCs that still have the older PowerShell updater. Until a release carries `smart-connector.json`, the program falls back to `latest.json`. After an update from a script-free release, the scripts that older versions left in the install folder (outside the skill library) are deleted, because the AI apps, Revit and AutoCAD now start `bin\SmartConnector.exe`.
- Fixed: in the setup window, text could cover other text (the title cut off, descriptions hidden behind the next box, the progress bar under the step name) on screens where text is drawn larger than the layout expects. Every page now measures its text after it is filled and moves anything that would overlap down, boxes grow to hold their text, and a page that is still too tall scrolls. Setup also writes one line to its log with the display scale and window size.
- The Revit add-in is now compiled in the automated tests with the same Windows compiler the PCs use, against the Revit 2024 API reference assemblies.
- Detail Generator, paper mode: notes are now leaders (the office Multiple Leader Lab block, or a native multileader), levels use the level indicator block with elevation and description, view titles use DWG-VIEWTITLE, and `layer_scheme` uses the office counter-sheet layers when the drawing has them. Notes follow the office wording (`18mm THK MDF ...`). Not yet run in AutoCAD.
