Smart Connector for Autodesk Revit and AutoCAD 1.2.3

New in 1.2.3 (following long Revit requests without waiting blind; everything from 1.2.2 below is included):
- `get_job` now takes `wait_seconds` (1 to 110, with `job_id`). When a Revit request outlives its `execute_csharp` call, the AI app follows it with `get_job`, which used to answer at once: Claude and Codex then paused in a shell between checks (for example 45 s, then 90 s) and the result waited for the pause to end even when Revit had finished seconds earlier. With `wait_seconds` the Revit add-in holds the answer until the job finishes, is cancelled or expires, and answers within a quarter of a second of that; when the time is up it answers with the current state and progress, and the next `get_job` call waits again. The wait runs on the add-in's pipe thread, not on Revit's own thread, so Revit keeps working and `connection_status` and other `get_job` calls still answer meanwhile. `get_job` with `cancel=true` never waits.
- The tool descriptions, the connector's instructions, the "still running" and "not started yet" job messages, the `revit-csharp-runner` and `revit-revision-clouds` workflows and the Revit timeout rule now tell the AI app to use `wait_seconds` and never to sleep or pause between `get_job` calls.
- The new add-in is loaded the next time Revit starts: close Revit and open it again after the update. Until then, and with an add-in from an earlier version, `get_job` answers at once as before; the connector sends `wait_seconds` only when it is asked for, so the two still work together.

Not verified in live Revit: the connector and the add-in compile and pass the offline tests (a stand-in add-in checks that `wait_seconds` reaches the pipe and that values above 110 are refused), not yet a long dry run in Revit followed with `get_job`.

Smart Connector for Autodesk Revit and AutoCAD 1.2.2

New in 1.2.2 (Claude Desktop from the Microsoft Store; everything from 1.2.1 below is included):
- Fixed: Smart Connector did not appear in Claude Desktop 6.x from the Microsoft Store although setup reported it as connected. That version reads a claude_desktop_config.json in another place than the two setup wrote to (%APPDATA%\Claude and the package's LocalCache\Roaming\Claude). Setup, Repair and the reconnect after an update now also search AppData for every claude_desktop_config.json (up to eight folders deep, at most 15 seconds, cache and browser folders skipped, linked folders not followed) and add the Smart Connector entry to each, keeping every other server and setting. A file found this way that cannot be read is reported in the setup log and left unchanged; it does not fail setup.
- The files that were updated are remembered in %LOCALAPPDATA%\AutodeskMcpConnector\claude-desktop-configs.txt. The Smart Connector app and the end of setup now report Claude Desktop as connected only when every one of these files has the entry (before, one file was enough, so a PC could show "connected" while Claude read another file), and the setup log lists each file.
- PCs on 1.2.1: the update is installed by 1.2.1's program, and the first start of 1.2.2 reconnects the AI apps in the background with this code, as in 1.2.1. Quit Claude Desktop from the system tray and reopen it once afterwards.

Not verified on a real PC: the search was tested offline with a config placed outside the standard folders, not yet with Claude Desktop 6.x itself; the manual repair that used the same approach made Smart Connector appear on the PC that reported the problem.

Smart Connector for Autodesk Revit and AutoCAD 1.2.1

New in 1.2.1 (AI apps reliably connected, offline DWG tools and open team joining; everything from 1.2.0 below is included):
- Fixed: on PCs with Claude Desktop from the Microsoft Store, setup could leave Claude and Codex without Smart Connector. The Store puts a Claude.exe start alias in %LOCALAPPDATA%\Microsoft\WindowsApps, which is on every user's PATH, and setup took it for the Claude Code command-line tool: it ran `mcp add` against Claude Desktop, so either nothing was registered while setup reported success, or Claude Desktop opened and setup waited at the Claude Code step until it was closed, before Claude Desktop itself was connected. Setup and the status checks now ignore that folder for `claude` (and use it for `codex` only as a last resort), and never treat Claude Desktop's own program folders as Claude Code. The setup window no longer ticks Claude Code as installed on such PCs.
- Every Codex and Claude Code registration is now read back from the app's own settings file (Codex's config.toml; Claude Code's .claude.json). If the command-line tool failed, did not answer within 90 seconds (it is then stopped), or reported success without writing the entry, setup writes the entry into that file itself, keeping every other server and setting. A failing `codex mcp add` therefore no longer leaves Codex (or ChatGPT Desktop, which reads the same file) unconnected.
- PCs that update from 1.2.0: an update is installed by the previous version's program, which connects the AI apps with its own (unfixed) code. So the first time 1.2.1 starts after the update (opening Smart Connector, a Revit or AutoCAD button, the daily update check, or Claude starting the connector), it connects the AI apps once more in the background with the fixed code. It never closes Claude Desktop: restart Claude Desktop, Claude Code and Codex once afterwards. It runs only from the installed program after setup has finished, once per version; the outcome is in %LOCALAPPDATA%\AutodeskMcpConnector\ai-apps-connected.json and ai-apps.log, and a failure is reported to the administrator like a failed tool on PCs that joined the team.
- The setup window and the app now give the Codex and Claude Code entry its real name, smart-connector (they still said autodesk).
- Offline DWG tools (new; the connector compiles and its tests pass in CI, but the bundled programs have not yet been run on a real drawing on Windows): `dwg_inspect` lists the layers of a closed .dwg and searches its text, and `dwg_convert` writes a DXF, a JSON file, a DWG saved as another version (r12 to r2018) or the drawing's preview image. They need no AutoCAD session. A conversion always writes a new file next to the source (or in `output_dir`), uses a numbered name instead of overwriting, and never changes the source. They start the LibreDWG programs from `bin\libredwg` as separate programs (LibreDWG is GPL-3.0-or-later; its licence text and source offer are installed beside them). LibreDWG is not AutoCAD: a rewritten DWG can lose dynamic blocks, proxy objects, solids and annotative detail, so open and audit it in AutoCAD before it goes to an authority. The approved workflow `libredwg-offline-dwg` asks for a yes before any conversion. A connector installed without the LibreDWG pack answers that the tools are not installed.
- Joining the team skill service no longer needs a team code: setup has no code box. A new PC joins as waiting and every skill-service call answers that it is waiting for the administrator until the owner approves it, in the Notion Team members database (Status Active; Blocked refuses) or on the dashboard; approvals apply within 10 minutes. Older team installers keep working.

Not verified on a real Windows PC with Claude Desktop from the Store: the alias fix and the background reconnect compile and pass the offline engine tests (fake codex and claude tools, a fake WindowsApps folder), not yet a live install.

Smart Connector for Autodesk Revit and AutoCAD 1.2.0

New in 1.2.0 (AutoCAD Detail Generator and connector safety; everything from 1.1.0 below is included):
- Several views on one sheet: a plan and two sections now draw together on one layout, each with its own viewport and the office annotation. Each result reports `paper_footprint` (the sheet area the view needs) so views can be checked for overlap, and `sheet_size_mm`; a view that does not fit the layout's paper, or that overlaps a viewport already on the layout, gets a warning before anything is drawn.
- `prepare_layout` (new tool): sets a layout's paper size and orientation (ISO A0 to A4, landscape or portrait) through its page setup, for a freshly opened drawing whose layout reads 0 x 0. It needs a dry run and the user's yes like every change, reads the size back, and does not save.
- `drawing_info` now returns each layout's sheet size after rotation, plot rotation, paper-space object count and existing viewports, and marks a layout with no usable paper size.
- The dry-run rule works across views: the approval is kept for the whole brief, so a view drawn after another (which creates layers) is no longer refused after its own dry run.
- A busy AutoCAD no longer breaks a run: a call that AutoCAD rejects ("call rejected by callee") is waited out and retried step by step, a plan that fails is rolled back completely (including when AutoCAD stays busy during the rollback), and if AutoCAD stays busy the message says where.
- Viewports: the first viewport on a fresh layout is made even when the layout's block is not yet paper space, the zoom is tried twice before the Target fallback, and the result says which method was used.
- Revit ribbon: the Smart Connector tab now has one panel with Connect, Status and Skills Sync, and a More menu (Browse Skills, Check updates, Settings, Diagnostics, Help), instead of eight buttons in three panels. The icons are flat line icons, a blue for the main action and a grey for the rest, with about 3:1 contrast on light and dark themes.
- AutoCAD panel: on the Add-ins tab, an AI Markup panel (AI Markup, Clear Markup) now comes first, then Smart Connector with Connect, Status and Skills Sync: five buttons instead of seven. Check Updates and Settings are reached through Connect (the app) and stay available as the commands SACCHECKUPDATES and SACSETTINGS. The icons are the same flat line icons as in Revit.
- Setup window: three steps (Terms, Choose, Install) in a step bar under a light header, instead of six steps in a navy side rail. The system check page only appears when the computer needs attention (Windows or .NET not ready, or an unsupported Revit version); otherwise the Choose page shows what was found, and the AI connections are explained there. Choose ends with Install.
- Docs: the detail-generator skill and references describe the sheet layout rules (no doubled overall dimensions, one note per part), the viewport layer (`AO-MV` with the office scheme) and the live-check results.
- Revit, found in a failed session on a heavily linked model (not yet run in live Revit; the connector and the add-in compile and pass simulated tests):
  - Errors are typed. A compile or runtime error in your own code now comes back as `[compile_error]` (with the line numbers of your code and a hint for the usual mistakes: `doc` instead of `document`, `?.`, string interpolation) or `[runtime_error]`; other add-in answers come back as `[document_changed]`, `[commit_failed]`, `[busy]`, `[invalid_request]` or `[revit_error]`. "Revit session is not available" now means a lost connection only. Before, every add-in error was reported as that.
  - `execute_csharp` documents the runner contract in its own description: the variables (`application`, `document`, `parametersJson`), the C# 5 language level and the namespaces already imported.
  - A request that outlives its wait is no longer lost. `execute_csharp` waits `wait_seconds` (default 60, at most 110, was a fixed 120). If Revit is still working it answers `completed: false` with a `job_id`; the new read-only tool `get_job` returns the progress (a script can report it with `McpProgress.Report`) and later the result, or cancels a job Revit has not started. `background: true` returns the `job_id` at once. A request Revit never started is dropped and answered `[busy]`, so it cannot run late.
  - `connection_status` answers while Revit is busy and says why: `busy_state` is `idle`, `executing` (with the job and its progress), `queued` or `revit_busy`. The add-in pipe now accepts several clients at once and answers status and job questions without Revit's thread. `list_sessions` shows the same.
  - `execute_csharp` takes `dry_run: true` in transaction mode: it runs the code, rolls it back and returns the change counts (added, modified, deleted, by category).
  - New tools `revision_cloud_info` (revisions, the types in the Revision Cloud Tags category with `likely_tag`, and the primary view of each dependent view) and `create_revision_clouds` (revision clouds with a Comments value and a text note beside each, in plan views, at most 40 per call, primary views only, `dry_run`). Not yet run in Revit.
  - Revit rules RVT-005 to RVT-011 (runner contract, batch size, timeouts, primary views, cloud tag families, idle check, tool prefix change), the skill `revit-csharp-runner` updated, and the new skill `revit-revision-clouds`.
  - Follow-up fixes after review: a `background` request that Revit has not started within 5 minutes is cancelled instead of running late; `create_revision_clouds` rolls a failed item back whole (a cloud whose note failed is no longer left in the model) and sets Comments through the built-in parameter, so it works in any Revit display language; a dry run lists other documents the code changed (`other_documents_changed`), because it rolls back the active document only; `connection_status` looks again when its check waits behind a queued request, and `[busy]` names our own running job when that is the cause.
  - The PowerShell fallback bridge passes the add-in's typed errors through and accepts the new `execute_csharp` options; it has no `get_job`, `revision_cloud_info` or `create_revision_clouds`.
- Revit, from a field report on building custom column families (not yet run in live Revit; compiled and tested in CI):
  - `execute_csharp` in `manual` mode with `allow_model_changes=false` is a probe: family documents can be created, edited, saved and closed without granting model changes. The project runs inside a transaction group that is always rolled back; a project change is undone and reported as `[probe_changed_project]`. Saving or synchronizing any other non-family document is cancelled during a probe and a change to one is reported. If the code leaves a project transaction open or the rollback fails, that is added after the script's own error instead of replacing it.
  - A `[runtime_error]` names the script line (`at mcp_code.cs line N`) and the Revit API method that threw. Revit failure messages posted during the run, with their element ids, are added to any `execute_csharp` error (for example after "Document regeneration failed").
  - Skills: the C# runner skill adds the modes table and the geometry Options rule (DetailLevel and View cannot be set together); the family modelling skill adds the custom column from a plan polygon workflow and the reliable way to load an API-created family (`famDoc.LoadFamily(document)`). TESTING.md has a live "Revit execute_csharp regression".
- Error reports to the administrator (added after the first 1.2.0 build; compiled and tested offline, not yet run on Windows): when an AutoCAD or Revit tool fails on a PC that joined the team service, the connector sends the tool name, the error type and a cleaned error message (names, numbers, paths, file names and quoted text removed) about five seconds later, or at the next Skills Sync if offline, and notes when the same tool later worked. The service groups identical errors and lists them in a Notion "Connector failures" table. The terms of use (version 2026-11-16) list this, so joined users accept the terms again.

Not verified on a real AutoCAD: `prepare_layout` and the overlap warning with an existing viewport. Everything else above ran live on AutoCAD 2024 (24.3) with the S-shaped reception counter: plan 1:20, sections A-A and B-B 1:10 on one A1 sheet.

1.1.0:
Lean core: Smart Connector now runs nothing in the background. This removes the behaviour that antivirus programs such as Kaspersky treat as a PowerShell "agent", and it gives IT a much smaller footprint to approve.

- No scheduled tasks and no notification-area agent. Updating from 1.0.0 or an earlier beta removes the four tasks earlier versions created (connector agent, usage report, weekly Skills Sync, update alerts) and the agent's restart copy. The running agent exits after the update.
- Update checks happen when you open Revit, AutoCAD or Smart Connector, at most once a day: one small download of the public latest.json. You are asked "Update now" or "Later". Update now opens a visible update window, which waits for Revit and AutoCAD to close and then installs. Nothing installs without your choice.
- Weekly Skills Sync reminder: on team computers, when the last successful sync is more than a week old, Revit, AutoCAD and the Smart Connector app remind you once a day. Switch it off in Settings.
- Usage counts for the administrator's dashboard are sent only when you run Skills Sync, never on a schedule. Setup no longer starts a hidden Skills Sync after installing.
- Removed: the optional Claude remote gateway (a local web server published to the internet through a Cloudflare tunnel). On PCs that used it, the update stops it, removes its start-up entry and deletes its stored credentials. Administrators should also revoke those tunnels in Cloudflare. Claude Desktop, Claude Code and Codex on the same PC work as before.
- In AutoCAD the daily check starts with the first Smart Connector button you use in a session. Loading anything at AutoCAD startup made AutoCAD ask SECURELOAD for every drawing, so that is avoided.
- Setup file: the setup .exe now only installs files (the connector and a Start menu entry) and runs no program or script. Open Smart Connector from the Start menu to finish: the setup window asks which AI apps and Autodesk programs to connect, as before. The Start menu entry opens the installed Smart Connector program, so no script runs from it.
- Compiled MCP server: Claude and Codex now start `bin\SmartConnector.exe`, a compiled program, instead of running the PowerShell bridge scripts. It offers the same Revit and AutoCAD tools with the same arguments and safety checks (one model change at a time, read-only tools stay read-only, skill files are read only from the approved folders). It is compiled by the release build, never on your PC. Setup re-points Claude Desktop, Claude Code and Codex to it; an install without it keeps using the PowerShell bridge. Before an update replaces the files, a running copy of the connector is closed; Claude and Codex start it again the next time they open (setup already restarts Claude Desktop when it re-points it).
- Compiled windows: the Smart Connector app, the setup window and the Skills Sync, Check Updates and Connection Status windows are now part of `bin\SmartConnector.exe` instead of PowerShell scripts, with the same sections, wording and look. The Start menu entry, the Revit and AutoCAD buttons and the end of setup open the program; the work behind the buttons (install, repair, Skills Sync, update check) still runs the existing setup scripts, and the update window stays as it was. An install without the program uses the PowerShell windows as before.
- Compiled Skills Sync: the Skills Sync button in Revit and AutoCAD, the Smart Connector app and the usage upload now run inside `bin\SmartConnector.exe` (`SmartConnector.exe skills sync`, `preview`, `collect`, `submit`, `usage`, `codex-sync`, `retire-tasks`, `configure` and `initialize`) instead of PowerShell scripts. They read and write the same files under `%LOCALAPPDATA%\AutodeskMcpSkillCollection`, send the same requests to the team skill service, apply the same checks (credentials, personal paths, client locations, e-mail addresses and links stay out of every submission), keep the same ledgers and the same log and result text. The PowerShell scripts stay in the package as the fallback for a copy taken from the repository, where `bin\SmartConnector.exe` is not installed.
- Compiled install engine: setup, Repair and updates now run inside `bin\SmartConnector.exe` (`SmartConnector.exe engine --action Install|Update|CheckUpdate|Status|...`) instead of `installer\Setup-BimCad.ps1`, with the same steps, messages and results. Installing the files, connecting Claude Desktop, Claude Code and Codex, the AutoCAD panel, the Revit add-in build, joining the team service and the update check no longer start PowerShell. The update no longer swaps the whole install folder: it downloads and verifies the release, stops only the other Smart Connector programs of this install, and replaces the files in place. A file in use (including the program itself while it runs the update) is set aside as `<name>.old` and deleted the next time any Smart Connector command starts; if the replacement fails, everything is put back. The update window (`SmartConnector.exe action --action InstallUpdate`) is part of the program too, and Revit and AutoCAD open it. An install without the program (a copy taken from the repository) keeps using the PowerShell scripts.
- Setup file without scripts: the setup .exe now installs only the compiled program (`bin\SmartConnector.exe`) and its data (icons, the skill library, the Revit and AutoCAD source files). No PowerShell, batch or other script of the connector is installed; the first open, the windows, Repair, updates and Skills Sync all run inside the program. Helper scripts that some approved skills carry inside the skill library are unchanged. A copy of the connector taken from the repository still contains the scripts and keeps using them.

No team code is needed (since 2026-11-21). A new PC waits for the administrator's approval: the administrator is @mentioned in Notion when someone joins, and sets the PC's Status in Team members to Active (approve) or Blocked (deny), applied within 10 minutes, or uses Approve/Deny on the dashboard.
